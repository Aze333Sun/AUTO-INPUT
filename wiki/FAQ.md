# 常见问题

## 安装问题

### 插件安装后没有自动切换输入法

**原因：** 插件需要重启 IDE 才能生效。

**解决：**
1. 安装插件后重启 IDE
2. 手动切换一次输入法，让插件学习当前窗口的默认状态
3. 之后插件会根据光标位置自动切换

### 安装时提示版本不兼容

**原因：** IDE 版本低于 2024.3.3。

**解决：**
1. 升级 IDE 到 2024.3.3 或更高版本
2. 或使用旧版本的插件（如果有）

### 本地构建失败

**可能原因：**
1. JDK 版本不正确（需要 17 或 21）
2. Maven 版本过低（需要 3.6+）
3. 网络连接问题（无法下载依赖）

**解决：**
```bash
# 检查 JDK 版本
java -version

# 检查 Maven 版本
mvn -version

# 清理并重新构建
mvn clean package
```

## 使用问题

### 切换不够灵敏 / 有时不切换

**可能原因：**
1. 光标移动太快，触发了 100ms 防抖间隔
2. PSI 文档尚未提交（插件会在后台提交，但可能有延迟）
3. 在工具窗口（Terminal、Build 等）中，插件默认使用英文

**解决：** 稍等片刻再操作，或手动切换一次。

### 字符串中的中文没有触发切换

**原因：** 字符串字面量在代码区域，不在注释区域。

**说明：** 这是正常行为。插件只在注释区域切换到中文输入法，字符串中的中文不会触发切换。

### 工具窗口中没有自动切换

**原因：** 工具窗口（Terminal、Build、Run 等）默认使用英文输入法。

**说明：** 这是设计行为。工具窗口通常用于命令行操作，需要英文输入法。

### 切换编辑器后输入法没有变化

**可能原因：**
1. 新编辑器的光标位置与之前相同
2. 插件检测到不需要切换

**解决：** 在新编辑器中点击不同位置，观察输入法是否切换。

## IdeaVim 问题

### IdeaVim 模式下切换异常

**检查：**
1. 确认 IdeaVIM 插件已正确安装（版本 2.22.0+）
2. 插件通过 `Class.forName()` 检测 IdeaVim，如果检测失败会回退到普通模式

**解决：**
1. 重启 IDE，确保 IdeaVIM 插件启用
2. 检查 IdeaVIM 版本是否兼容
3. 查看日志中是否有 `现在是普通模式`（表示 IdeaVim 未检测到）

### IdeaVim Insert 模式下没有自动切换

**可能原因：**
1. IdeaVim 的 ModeChangeListener 未正确注册
2. Vim 模式检测失败

**解决：**
1. 重启 IDE
2. 检查日志中是否有 `成功添加Vim模式变更监听器`
3. 确保 IdeaVIM 插件已启用

### IdeaVim Normal 模式下输入了中文

**可能原因：**
1. ISINSERT 变量未正确更新
2. 输入法切换延迟

**解决：** 手动切换到英文输入法，或重启 IDE。

## 输入法问题

### 不支持我的输入法

**已知不支持：** 微信输入法

**原理：** 插件通过 Windows IME API（`imm32.dll`）查询输入法状态。如果输入法不标准 IME 接口，可能无法检测。

**解决：** 尝试切换到微软拼音、搜狗输入法或百度输入法。

### 输入法切换后又自动切换回来

**可能原因：**
1. 光标位置变化触发了新的切换
2. 多个监听器同时触发

**解决：** 检查日志中的切换记录，确认切换逻辑是否正确。

### 输入法切换时有延迟

**原因：** 插件有 100ms 的防抖间隔，避免频繁切换。

**说明：** 这是正常行为。如果延迟过长，可能是系统性能问题。

## 平台问题

### Linux / macOS 能用吗？

**当前不支持。** 插件通过 JNA 调用 Windows 原生 API（`imm32.dll`、`user32.dll`），仅支持 Windows。

**计划：** 未来版本可能添加 Linux 支持。由于开发者没有 Mac，暂无 macOS 支持计划。

### Windows 版本要求

- Windows 10 或更高版本
- 需要支持 IMM32 API

## 兼容性问题

### 插件与其他输入法插件冲突

如果安装了其他输入法管理插件，可能会产生冲突。建议：
1. 禁用其他输入法相关插件
2. 仅保留 AUTO-INPUT-CH-EN

### 插件与其他 IdeaVim 插件冲突

如果安装了其他 IdeaVim 扩展，可能会产生冲突。建议：
1. 禁用其他 IdeaVim 扩展
2. 仅保留 AUTO-INPUT-CH-EN

## 性能问题

### 插件占用资源大吗？

插件非常轻量：
- 仅监听光标变化和焦点事件
- 不进行后台轮询
- JNA 调用仅在需要切换时执行
- 100ms 防抖避免频繁调用

### 插件导致 IDE 卡顿

**可能原因：**
1. PSI 操作频繁
2. JNA 调用阻塞
3. 系统性能不足

**解决：**
1. 检查系统资源使用情况
2. 查看 IDE 日志中的错误信息
3. 尝试重启 IDE

## 日志问题

### 如何查看插件日志？

插件日志输出到 IDE 的 stdout。在沙盒 IDE 中运行时，日志位于：
```
target/idea-sandbox/system/log/idea.log
```

搜索关键字：
- `现在是普通模式` — 普通模式启动
- `现在无vim模式` — IdeaVim 未检测到
- `按下 Shift` — 输入法切换
- `imm加载成功` — JNA 库加载成功
- `imm加载失败` — JNA 库加载失败

### 日志中显示 imm 加载失败

**原因：** JNA 无法加载 `imm32.dll` 库。

**解决：**
1. 确保在 Windows 系统上运行
2. 检查系统 PATH 环境变量
3. 尝试重启 IDE

### 日志中显示获取输入法异常

**原因：** 无法获取当前输入法状态。

**解决：**
1. 检查输入法是否正常工作
2. 尝试手动切换输入法
3. 重启 IDE
